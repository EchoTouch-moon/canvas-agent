# Canvas Agent 产品形态与核心用户流程

## 1. 产品形态原则

```text
底层：统一项目状态与关系数据
主要工作：工作台、对象工作区、Context Composer
过程理解：Run 时间线
高级探索：局部 Canvas
```

Canvas 不能成为所有功能的唯一入口。

## 2. 导航

```text
项目
├─ 工作台
├─ 大纲
├─ 任务
├─ 上下文
├─ 关系地图
├─ 执行记录
├─ 产物
└─ 设置
```

## 3. 核心页面

### 3.1 项目工作台

回答：当前发生什么、接下来做什么。

展示：

- 当前项目目标和 Active Baseline；
- 正在执行或等待评审的 Task；
- 失败、暂停或等待输入的 Run；
- 待处理 Approval；
- 最近 Artifact；
- Stale / Diverged Snapshot 提醒；
- 推荐下一步。

### 3.2 项目大纲

回答：项目由什么组成。

- 读取 PARENT_OF；
- 提供稳定导航；
- 支持创建 Node 和进入对象工作区；
- 不承担复杂非层级关系展示。

### 3.3 对象工作区

Node 或 Task 的日常工作位置，包含：

- 标题、类型、版本和状态；
- 内容、目标、Non-goals、验收条件；
- 关系、依赖和影响；
- 相关代码路径；
- Snapshot、Run、Artifact 和历史；
- Agent 提议的版本或 Edge；
- 评审与确认操作。

### 3.4 Context Composer

建议三栏：

```text
候选上下文 | 已选择上下文 | 分析与预览
```

显示推荐原因、版本、权威、Token、冲突和最终渲染预览。

### 3.5 Run 视图

MVP 先显示：

- Run 状态和 Outcome；
- TaskSpecVersion、Snapshot 和 Revision；
- 当前 Worker / ExecutionRequest；
- 关键步骤；
- Diff、测试和 Agent Summary；
- 用户输入或审批请求。

完整时间线在真实事件协议稳定后扩展。

### 3.6 Artifact 视图

管理代码 Patch、测试报告、迁移脚本和 Agent Summary，并明确：

- 来源 Run；
- 对应 RepositoryRevision；
- 是否已接受、应用或拒绝；
- 作为哪个 AcceptanceCriterion 的证据。

### 3.7 Canvas Map

MVP 后期只做局部关系图：

```text
当前 Node
+ 一跳强关系
+ 用户按需展开
```

支持关系过滤；坐标不表达业务事实；详细内容在侧栏或对象工作区。

## 4. 核心流程

### 4.1 从 Idea 创建项目

```text
输入 Idea
→ 系统提出 Goal、Requirement、Constraint 候选
→ 用户确认和编辑 NodeDraft
→ 保存 NodeVersion
→ 建立必要 Edge
→ 创建 ProjectBaseline v1 Draft
→ 用户激活
```

### 4.2 Bootstrap 第一版

```text
基于 Baseline 创建 BOOTSTRAP_PROJECT Task
→ 确认 TaskSpecVersion 与验收条件
→ Context Composer 组装 Snapshot
→ 创建 Run / ExecutionRequest
→ Worker 在隔离工作区生成代码和测试
→ 用户审查 Artifact
→ Task 完成
→ 形成第一版代码 Baseline
```

### 4.3 实现一次需求变化

```text
创建新 Requirement 或 NodeVersion
→ 建立/复核 Edge
→ 创建 IMPLEMENT_CHANGE Task
→ 选择相关设计、约束、代码和历史失败
→ 冻结新 Snapshot
→ Worker 修改与测试
→ 验收
→ Baseline N+1
```

### 4.4 处理失败

```text
Run 产生 PARTIAL / FAILED
→ 查看错误、Diff 和测试报告
→ 判断是否只是 Worker 中断
   ├─ 是：从 Checkpoint 继续原 Run
   └─ 否：调整 Snapshot 或任务后创建新 Run
```

### 4.5 影响分析

```text
打开 Node
→ 查看 DEPENDS_ON / IMPLEMENTS / CONSTRAINS
→ 局部 Canvas 展示影响范围
→ 为需要重新验证的对象创建 Task
```

## 5. Canvas 交互约束

- 默认不展示完整项目；
- 只显示摘要，不把长文档塞进节点；
- 关系类型可过滤；
- 视觉选择必须能转换为 SavedView、Task Scope 或 ContextSnapshot；
- 时间过程使用时间线；
- 高密度比较使用表格或矩阵；
- 用户不应为了使用产品而持续整理画布。
