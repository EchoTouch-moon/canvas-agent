# Canvas Agent 核心领域模型与业务规则

## 1. 聚合总览

```text
Project
├─ Node / NodeDraft / NodeVersion
├─ Edge
├─ ProjectBaseline
├─ Task / TaskSpecVersion / AcceptanceCriterion
├─ ContextSnapshot
├─ Run / Approval
├─ ExecutionRequest
└─ SavedView
```

## 2. Project 与图结构

- Node 和 Edge 直接属于 Project；
- 不设置强制 Graph 业务容器；
- 项目逻辑图由 Node + Edge 自然形成；
- SavedView 保存坐标、缩放、过滤和显示范围；
- 删除视图不删除项目事实。

## 3. Node

### 3.1 定义

Node 是长期稳定、可独立引用的项目语义身份。

### 3.2 MVP 类型

```text
IDEA, GOAL, REQUIREMENT, CONSTRAINT,
DESIGN, DECISION, COMPONENT
```

### 3.3 成为 Node 的判断

至少具备两项通常才值得节点化：

- 需要被独立引用；
- 会长期演化；
- 修改时需要影响分析；
- 可能进入 Baseline；
- 需要建立明确语义关系。

### 3.4 不作为 Node

Task、Run、Artifact、聊天、工具调用、普通代码文件、每条日志和每条测试结果。

### 3.5 版本

```text
NodeDraft：可变编辑稿
NodeVersion：不可变正式内容
```

Baseline 和冻结 Snapshot 只能引用 NodeVersion。

同一问题的答案变化 → 新 NodeVersion；出现独立问题或能力 → 新 Node。

### 3.6 生命周期

```text
ACTIVE, DEPRECATED, ARCHIVED
```

被历史对象引用后不得硬删除。

## 4. Edge

### 4.1 定义

Edge 是 Node 之间的长期语义关系，仅连接 Node，可选锚定 NodeVersion。

### 4.2 类型与固定方向

```text
PARENT_OF：父级 → 子级
DEPENDS_ON：依赖者 → 被依赖者
IMPLEMENTS：实现者 → 被实现对象
CONSTRAINS：约束 → 被约束对象
SUPERSEDES：新对象 → 被替代对象
DERIVED_FROM：新对象 → 来源对象
RELATED_TO：弱关联，查询时可按对称关系处理
```

### 4.3 生命周期

```text
PROPOSED, ACTIVE, NEEDS_REVIEW, SUPERSEDED, ARCHIVED
```

MVP 不设置 EdgeVersion。关系语义改变时创建新 Edge，并替代旧 Edge。

### 4.4 校验

- 禁止自连接；
- PARENT_OF、SUPERSEDES 禁止循环；
- DEPENDS_ON 循环允许保存但必须警告；
- 自动发现的 Edge 默认 PROPOSED；
- NodeVersion 更新不自动删除 Edge，而是按规则进入 NEEDS_REVIEW。

## 5. ProjectBaseline

### 5.1 定义

某阶段被正式确认的项目共识。

### 5.2 内容

- NodeVersion；
- 当时有效 Edge；
- 可选 RepositoryRevision；
- 正式范围和验收信息。

### 5.3 状态

```text
DRAFT → ACTIVE → SUPERSEDED
```

同一 Project 同时只有一个 Active Baseline。激活后不可变。

## 6. Task

### 6.1 定义

具有明确目标、范围和验收条件的工作单元。

### 6.2 结构

```text
Task：稳定身份和生命周期
TaskDraft：规划草稿
TaskSpecVersion：不可变任务定义
TaskTarget：关联一个或多个 Node / NodeVersion
```

### 6.3 MVP 类型

```text
BOOTSTRAP_PROJECT
IMPLEMENT_CHANGE
```

### 6.4 新任务还是新版本

- 核心目标不变，调整范围或验收 → 新 TaskSpecVersion；
- 可独立完成、独立验收的新目标 → 新 Task；
- 同一任务执行失败 → 新 Run，不是新 Task。

### 6.5 状态

```text
DRAFT, READY, IN_PROGRESS, WAITING_REVIEW,
COMPLETED, CANCELLED, ARCHIVED
```

BLOCKED、NEEDS_CHANGES 为派生状态。

## 7. AcceptanceCriterion

- 属于 TaskSpecVersion；
- 描述最终结果，不描述实施步骤；
- 每次 Run 通过 AcceptanceEvaluation 保存验证结果；
- 验证方式：AUTOMATED_TEST、MANUAL_REVIEW、ARTIFACT_CHECK、STRUCTURED_ASSERTION；
- 结果：NOT_EVALUATED、PASSED、FAILED、WAIVED；
- WAIVED 必须记录人、时间和原因；
- Task 完成必须指定 completion_run_id，必要验收来自同一完成候选或相同最终 RepositoryRevision。

## 8. TaskDependency

- 表示工作计划依赖，不等同于 Node 的 DEPENDS_ON；
- 类型：HARD_BLOCK、SOFT_ORDER；
- 循环全部禁止；
- Node 依赖可用于建议 TaskDependency，但不能自动生成正式计划。

## 9. Run

### 9.1 生命周期

```text
CREATED, QUEUED, PREPARING, RUNNING,
WAITING_INPUT, WAITING_APPROVAL,
PAUSED, INTERRUPTED, FINISHED
```

### 9.2 Outcome

```text
SUCCEEDED, PARTIAL, FAILED, CANCELLED, TIMED_OUT
```

### 9.3 恢复规则

继续原 Run 要求 TaskSpecVersion、ContextSnapshot、RepositoryRevision、Agent 配置和目标不变，并存在有效 Checkpoint。

以下必须创建新 Run：

- 修改任务规格；
- 修改 Snapshot；
- 修改基础代码版本；
- 更换模型做结果对比；
- 前一个 Run 已 FINISHED；
- 用户要求重新生成或换方案。

## 10. Approval

### 10.1 状态

```text
PENDING, APPROVED, REJECTED, EXPIRED, CANCELLED, CONSUMED
```

### 10.2 规则

- 必须绑定精确 Run、动作、参数 Hash 和代码版本；
- 默认单次使用；
- APPROVED 不是已执行；
- 实际动作完成后才是 CONSUMED；
- 普通问题使用 Input Request，不使用 Approval；
- 结果验收使用 AcceptanceEvaluation，不使用 Approval。

## 11. 不可变与审计

- 已冻结 Baseline、Snapshot、NodeVersion、TaskSpecVersion 不得修改；
- 已 FINISHED Run 不得重开；
- 重要状态转换必须形成追加式事件；
- 状态转换通过服务端命令校验，不允许界面任意改字段；
- 并发操作使用乐观锁、幂等键和 compare-and-set。
