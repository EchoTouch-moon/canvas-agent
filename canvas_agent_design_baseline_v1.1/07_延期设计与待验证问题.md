# Canvas Agent 延期设计与待验证问题

## 1. 本文档目的

以下内容不是遗漏，而是明确延期。开发到对应模块时再基于真实数据进行一次小范围设计评审。

## 2. RunEvent【DEFERRED】

开发 Run 时间线前确认：

- 最小事件目录；
- sequence、event_id 和去重规则；
- 状态事件与日志事件如何分离；
- 事件重放与当前状态的关系；
- Agent 文本、系统状态、用户输入、工具事件的分类；
- 大型日志是否进入 Blob。

MVP 允许先使用通用结构：

```text
id, run_id, sequence, event_type, payload_json, created_at
```

## 3. ToolInvocation【DEFERRED】

接入真实工具前确认：

- 输入参数保存与脱敏；
- 输出保存为 JSON、文本或 Blob；
- 有副作用与无副作用工具分类；
- 幂等键和安全重试；
- 超时、取消和部分输出；
- Approval 与工具参数 Hash 的绑定。

## 4. Checkpoint【DEFERRED】

实现中断恢复前确认：

- 是保存 Agent 内部状态，还是只保存可重建的外部状态；
- 工作区快照、执行计划和待办步骤的表示；
- 已发生副作用列表；
- 恢复兼容版本；
- Checkpoint 有效期；
- 不同 Agent CLI 是否能够真正恢复同一推理过程。

风险：部分 Agent CLI 只能重新启动并提供历史摘要，而不能原位恢复隐藏状态。因此“恢复”可能是工程恢复，而非比特级恢复。

## 5. Artifact【DEFERRED】

实现结果评审前确认：

- Artifact 类型注册表；
- Code Patch、Test Report、Migration、Agent Summary 的统一字段；
- 接受、拒绝、应用、撤回状态；
- Artifact 如何成为 AcceptanceEvaluation 证据；
- Artifact 如何建议 NodeVersion、Edge 和 Baseline Draft；
- 一个 Artifact 是否可属于多个 Run 或只属于一个 Run。

## 6. Worker 适配【DEFERRED】

确定第一个 Worker 后确认：

- Codex CLI / Claude Code / 其他 Agent 的输入方式；
- 如何提供 Snapshot；
- 如何监听工具和文本事件；
- 如何获取 Diff、测试和成本；
- 是否支持暂停、继续和审批；
- 进程生命周期和超时。

## 7. 技术架构【NEXT】

开工前需确认但尚未决定：

- Tauri、Electron 或 Web + Local Service；
- 应用服务语言；
- PostgreSQL、SQLite 或组合；
- Blob 的本地目录结构；
- 后台 Worker 进程通信；
- Git Worktree 管理方式；
- 本地密钥和 Agent CLI 凭证处理。

## 8. 产品体验待验证

- 用户愿意维护多少 Node；
- 系统推荐多少上下文才不会造成负担；
- Edge 确认是否过于频繁；
- Context Composer 是否需要三栏布局；
- 用户是否理解 Baseline 与 Snapshot；
- 用户在什么时点愿意确认 Baseline；
- 一个 Task 的理想粒度；
- 是否需要把 NodeDraft 和正式版本在 UI 中明确区分。

## 9. 后置能力【OUT OF SCOPE】

- 多人实时协作；
- 多项目共享知识；
- 自定义 Node / Edge 类型；
- 图数据库；
- 向量化整个仓库；
- 自动上下文优化；
- 多 Agent 自主分工；
- 分布式 Worker；
- 企业权限、审计和计费；
- 完整全局 Canvas；
- 可视化工作流编排。

## 10. 触发设计评审的时点

```text
开始开发执行时间线 → 评审 RunEvent
接入第一个工具       → 评审 ToolInvocation
实现中断恢复         → 评审 Checkpoint
实现结果评审         → 评审 Artifact
实现局部 Canvas      → 评审 SavedView 与图查询
接入第二种 Agent     → 评审 Worker Adapter 与渲染层
```
