# UI-001: Complete the Canvas Agent UI foundation

## Task owner

GPT-5.6 Luna — visual task.

## Task goal

Turn the lead architect's representative shell into a polished, reusable Base UI + shadcn/ui Rhea foundation matching the four local reference images without copying fake screenshot data into product logic.

## Background and context

The product is a compact desktop productivity workbench: neutral surfaces, deep ink text, restrained indigo accent, borders over shadows, fixed semantic status colors, visible focus, light/dark parity and keyboard-first behavior.

Inspect all four PNG files in `canvas_agent_design_baseline_v1.1/` and read:

- `AGENTS.md`
- `canvas_agent_design_baseline_v1.1/10_UI设计与开发基线.md`
- `docs/architecture/implementation-baseline-v0.1.md`
- current `apps/desktop/src/renderer/**`

- Tailwind v4 + CSS variables
- shadcn `components.json`: Base UI / Rhea
- Existing representative AppShell, Button, Badge and domain status mapping
- MUSICDB data is a typed UI fixture only

## Implementation scope

You may modify only:

- `apps/desktop/src/renderer/**`
- `apps/desktop/components.json` only if a shadcn component add requires it
- `pnpm-lock.yaml` only as generated by adding an already approved UI dependency

Build/refine:

1. complete light/dark design tokens, typography, control heights, panel widths, focus and status semantics;
2. `components/ui`: Button, Badge, Input, Separator, Tabs, Tooltip, ScrollArea, Skeleton and Resizable using Base UI-backed shadcn output where available;
3. `components/app`: AppShell, AppSidebar, WorkspaceHeader, InspectorPanel, PageToolbar, EmptyState, LoadingBoundary and ErrorState;
4. `components/domain`: NodeTypeBadge, TaskStatusBadge, RunStatusBadge, RunOutcomeBadge, BaselineStatusBadge and SnapshotFreshnessBadge;
5. theme toggle and `Cmd/Ctrl+K` command-palette shell;
6. Story/demo route or component gallery covering states used by later pages.

## Prohibited scope

- Do not edit main/preload, domain/contracts, backend packages, ADRs or product baselines.
- Do not add full pages, persistence calls, real Worker controls or React Flow.
- Do not add MUI, Ant, Mantine, Chakra or a second visual system.
- Do not expose Electron/IPC directly from components.
- Do not hardcode screenshot counts, dates, user avatars or 2025 run IDs as product state.
- Do not change product terminology to match labels in the images when the documents disagree.

## Design constraints

- Default target: 1440px; complete workbench remains usable at 1180px.
- Inspector collapses before the main task becomes cramped; Sidebar supports icon mode.
- Status uses color + text/icon/shape; WCAG AA contrast for essential text and controls.
- Keyboard and focus behavior work without a mouse.
- Compactness comes from consistent control sizing and grouping, not tiny text.
- Components accept typed props; page-specific values do not enter `components/ui`.

## Acceptance criteria

1. **Given** light or dark theme, **when** the shell renders, **then** background, border, focus and all domain statuses remain legible and semantically consistent.
2. **Given** a 1440×1080 viewport, **then** the three-panel composition matches the local reference density and visual hierarchy without horizontal scrolling.
3. **Given** an 1180×820 viewport, **then** Inspector can collapse and navigation remains usable.
4. **Given** keyboard-only input, **then** primary navigation, theme toggle, command palette and collapsible panels are reachable with visible focus.
5. **Given** two pages use the same Task or Run state, **then** they import the same domain badge component rather than duplicate color logic.
